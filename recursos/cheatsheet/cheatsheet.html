Reglas de oro (no se rompen)

  • Bases de dev/staging son compartidas. Nada de POST/PUT/DELETE ni migraciones contra ellas sin que el equipo lo pida.
  • Producción jamás desde tu máquina: solo por el pipeline.
  • Migraciones automáticas al arrancar apagadas cuando apuntas a una base compartida.
  • config.json, certs/, .env, binarios y docs/ (swag) nunca en commits. Verifica: git check-ignore -v <archivo>.
  • No apagues la autenticación "para probar rápido": se te olvida prenderla.
  • Si tu servicio consume una cola compartida, no lo conectes desde local: le robas mensajes al entorno.
  • example: de Swagger nunca con valores reales.

Go: errores

var ErrNoExiste = errors.New("no existe")      // centinela
return fmt.Errorf("almacén %d: %w", id, err)   // %w envuelve
if errors.Is(err, ErrNoExiste) { }              // busca VALOR
var e *MiError; if errors.As(err, &e) { e.Codigo } // busca TIPO
func (e *MiError) Unwrap() error { return e.Causa }
  • Revisa err justo después de la llamada. Nunca compares por texto.
  • Entre capas, envuelve con contexto (%w o la librería de errores del equipo), no return err crudo.

// en gin: ctx.Request.Context()

var wg sync.WaitGroup; wg.Add(1); go func(){ defer wg.Done() }(); wg.Wait()
var mu sync.Mutex; mu.Lock(); defer mu.Unlock()

func Mapear[T, U any](xs []T, f func(T) U) []U { ... }
  • Gin atiende cada petición en su goroutine: estado compartido con Mutex. Detecta carreras con -race.

UnitOfWork + txOrDB

err := s.uow.Do(ctx, func(ctx context.Context) error {
  if err := s.writer.Insertar(ctx, a); err != nil { return err }
  return s.otro.Insertar(ctx, b)      // misma transacción (va en ctx)
})
  • Do commitea si fn devuelve nil: un return nil temprano persiste lo hecho. Para abortar sin error al cliente: centinela + IsCode fuera del Do.
  • Do anidado = transacción independiente, no savepoint. Abre una sola vez arriba.
  • Los adaptadores siempre usan txOrDB(ctx, r.db).

Receta: operación nueva

1 puerto (si hace falta) · 2 service (interfaz + Impl, valida, uow.Do si >1 escritura) · 3 test con fake · 4 adaptador(es) · 5 DTO -> mapper -> handler + swagger -> ruta después del middleware · 6 cableado en app.go · 7 swag init, build, vet, fmt, test, curl.

Nombres

Rol en inglés (Reader, Service, Impl), negocio en español (Almacen, PorID, Insertar). Los nombres en español no se renombran (contrato JSON, rutas, columnas). Un concepto = mismo nombre de archivo en todas las capas.

Errores estilo librería interna (pkg/apperr)

return nil, apperr.New(http.StatusNotFound, "El almacén no existe", err)
return nil, apperr.Wrap(err)                 // entre capas
if apperr.IsCode(err, http.StatusNotFound) { } // decidir
apperr.Response(err, ctx)                     // error del service
apperr.CtrlResponse(400, msg, err, ctx)       // error del borde HTTP
log.Printf("código %d: %v", apperr.Code(err), err)
4 trampas típicas (el dojo las trae a propósito):
1. AppError no tiene Unwrap(): errors.Is no ve la causa -> usa IsCode.
2. apperr.Wrap(nil) no es nil: si absorbes not-found, return nil, nil explícito.
3. apperr.New(code, msg, nil) revienta al responder: siempre causa (errors.New(msg)).
4. Nunca return err crudo entre paquetes.

Librería compartida: config, auth, ecosistema

  • Módulo privado: go env -w GOPRIVATE=github.com/tu-org/* + credencial git (SSH o token). Versiona con semver y tags vX.Y.Z.
  • Probar cambios sin publicar: replace github.com/tu-org/libs => ../libs en go.mod (nunca en commit) o go work.
  • config: si la librería cae en una config de prueba cuando no encuentra el archivo, no falla: lee el log de arranque si "no ves tus datos".
  • auth: JWT + autorización por rol (p. ej. casbin). Ruta nueva = 403 hasta darle permiso en cada entorno.
  • Token servicio a servicio (X-App-Token): solo entre tus servicios, nunca hacia terceros. Cliente HTTP siempre con timeout.
  • Parsear Authorization con strings.Cut, no Split(...)[1] (panic = 500 en vez de 401).
  • Trace: TraceID viaja en el ctx; pásalo siempre.
  • Shutdown: cada tarea en segundo plano respeta ctx.Done().
  • Leer el código de una dependencia: $(go env GOMODCACHE)/<módulo>@<versión>/ o go doc.

Proceso: del ticket a producción

Ticket -> rama feature/<ticket>-slug -> código + tests + swagger + migración -> verificación local -> PR (CI: build, vet, test, lint) -> revisión + QA en staging -> merge -> pipeline despliega a production.

Checklist antes de desplegar

  • Ruta nueva -> permisos/roles en cada entorno.
  • Llave nueva de config -> config.example.json + config de cada entorno antes del código.
  • Migración -> quién y cuándo se aplica en producción: coordínalo.
